# 民策通：从功能集合到一条服务流程

居民端核心优势是“有依据的政策关联、对话整理资料、本人确认下一步”。政府端核心优势是“材料核对、群众参与、送达跟进”。真实资格仍需正式渠道核实，站内申报和回执为虚构演示。

## 居民端只有三个一级入口

| 入口 | 用户眼前的问题 | 合并的能力 |
| --- | --- | --- |
| 为你 | 有什么与我有关？ | 政策推荐、待处理事项、提醒摘要和政策消息 |
| 找红通 | 接下来怎么办？ | 生活事件识别、官方来源、条件核对、对话整理、自动填写及最后本人确认 |
| 我的进度 | 刚才的事到哪一步了？ | 已有咨询、待核对表格、失败续办、虚拟申报回执及提醒管理 |

`/user.html` 和 `/resident.html` 使用同一控制器、同一会话和同一导航。旧的 `#hall`、`#messages`、`#search`、`#pilot` 深链仍可使用；`#desk` 对应找红通，`#services` 对应进度。

一级入口不再并列放置“政策搜索、办事大厅、消息、先行者、主动服务、图谱、空间”。搜索在首页和个人菜单内，先行者在政策共创入口内，提醒放进进度和按需打开的管理面板，展示图谱与立体空间放进“我的 → 探索与更多”。旧展示链接继续可用，但不是第二套主产品。旧 `/services.html` 居民书签回到统一进度页，`?tab=assistant` 回到找红通；嵌入管理面板与工作人员视图保留。

## 一条连续流程

1. 首页的生活话题只预填对话，不自动发送，也不据此给居民添加困难或健康标签。
2. 相关政策可以打开原文，再把解读需要交给同一个红通。
3. 提醒管理中选择办理，会携带本人所属的记录或通知回到同一对话，不在嵌入页另开聊天。
4. 推荐咨询和其实际办理事项在进度列表中合并展示，空白对话不占据进度。
5. 待核对事项可以续接原案例；已提交的虚拟申报可直接查看原回执，不创建新案例。

后台 `GET /api/agent/desk/journey` 为只读、居民隔离的摘要，不返回聊天、填写值、身份证信息或工具中间缓存。汇总页面不触发模型调用。资料、提交确认和撤回授权沿用原有后端规则。

## 政府端保持单屏

侧栏收成“材料核查、群众征询、服务跟进”。财报识别与核算并入材料核查，不再要求选择另一套工作流。原有财务深链与文档功能保留。

服务跟进包含提醒待办、虚拟受理和政策送达回复；数据资料库和连接设置放入“更多”，不占据主要操作区。界面不会自动发布政策、改变条件或代居民确认提交。

## 后续扩展约束

- 新能力先考虑接入上述流程，不直接增加一级导航。
- 展示方式与业务入口分开；不要通过历史展示生成器覆盖统一主入口。
- 没有匹配、没有读取成功与没有办理记录分别展示，不能把失败当作零条结果。
- 不展示虚构政策数量、虚构匹配率、虚构审批进度或正在执行的假动画。
- 保留减少动态效果设置、手机三栏导航、键盘可用性及资料修改路径。

## 验证

`npm test`、`npm run check`；`tests/product.browser.cjs` 覆盖首页话题、同一对话、办理续接、最终确认、回执、提醒转交、政策转交、居民入口兼容、政府跟进、手机宽度与零真实模型调用。已有文档审稿、表格修改、关怀、提醒、主动推荐和入场流程继续回归。
