# 政策找民的事件与主动跟进

本模块是民策通自己的业务适配，不安装或运行 DeepSeek Harness，不调用 shell 执行器，不消耗模型额度。设计参考 DeepSeek 研究原型 [事件接入](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/6337fc823ce20251c8de8085948165c81aaa701e/src/core/intake.ts)、[评估](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/6337fc823ce20251c8de8085948165c81aaa701e/src/core/evals.ts)与[授权模式](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/6337fc823ce20251c8de8085948165c81aaa701e/docs/002-authorization.md)。参考的是事件、评估和任务的划分，不宣称已接入 SuperAgent 或实现文章讨论的全部能力。

## 入口

- 政府端：服务跟进 → 事件与主动跟进。
- 居民端：右上角个人设置 → 主动跟进。先与红通建立事项，再选择事项、可选的准备完成日期，明确同意后开启订阅。
- 两端复用原有演示权限与居民 Bearer 身份。政府端仍为公开共创演示，不具备正式政府账户分权，仅用虚构数据。

## 业务规则

默认 `observe`，只保存判断。政府端选择“开启规则执行”后切换 `auto`，重新核验仍有效的观察记录才执行。切回观察模式暂停新增动作，不表示撤销已送达信息。

| 事件 | 来源与过滤 | 动作 |
| --- | --- | --- |
| 政策发布或版本变化 | 已保存的 publication，核对当前内容版本及登记截止日期 | 对已授权居民刷新官方目录推荐，生成站内核对待办；自定义草案和先行者递送仍需原有人工确认 |
| 本人明确的服务需求变化 | 已保存的需求标签变化与当前主动消息授权 | 重新匹配政策，复用原有去重；不记录聊天正文，不推断未表达的困难 |
| 办理准备缺项 | 本人明确订阅的事项，读取对应虚拟表单真实必填字段；排除已填写、拒绝提供的字段 | 提醒继续准备，不伪造正式补正通知 |
| 准备期限临近 | 本人登记日期的最后72小时 | 提前检查提醒；72小时是产品规则，不是法定期限 |
| 超过准备期限 | 本人登记日期已过，事项尚未确认准备稿或虚拟提交 | 一条居民提醒及一项工作人员核查待办，不认定真实政府办件超时 |

缺项、临期、超期按优先级合并为同一事项的当前提醒，状态变化后替换旧提醒。待办按待认领、已认领、已完成流转，工作人员确认完成会结束该事项订阅；居民可重新授权。本人暂停、确认准备稿、虚拟提交或删除事项后停止当前提醒。虚拟提交不表示真实申请办结。

## 执行和恢复

1. 从现有持久化业务状态产生事件；不提供任意文本事件注入接口，也不把聊天正文、身份证、联系方式或材料内容写入事件日志。
2. 初次安装建立政策游标，不回放历史目录；后续成功写请求结束后检查状态，进程存活时每分钟检查时间条件，重启后补查当前状态。
3. 事件有确定性ID、规则版本、判断理由、订阅代次和状态。先保存执行意图，再执行站内动作；重启恢复未完成动作并检查最新授权和事实。
4. 观察、执行、过期过滤和失败可查看。失败采用递增退避，最多尝试3次；扫描周期决定实际重试时间。每条事件对应至多一份提醒或待办，政策推荐复用原有去重。
5. 所有状态放在现有数据目录中的 `state.json`。免费云实例休眠期间不会检查；临时磁盘重置会丢失订阅、事件和回执。全天候跟进需另行配置常驻进程与持久化存储，本次不自动开通付费资源。

## 接口

| 接口 | 用途 |
| --- | --- |
| `GET /api/event-center/me` | 本人事项、订阅、提醒与判断记录 |
| `POST /api/event-center/me/watch` | 本人订阅或暂停：caseId、enabled，开启时 consent:true，可选 deadline 为 YYYY-MM-DD |
| `POST /api/event-center/me/notices/:id/read` | 本人提醒已读 |
| `GET /api/event-center/government` | 演示管理端判断记录与跟进待办，不包含个人表单正文 |
| `POST /api/event-center/government/mode` | mode:observe/auto、confirm:true |
| `POST /api/event-center/government/scan` | 检查当前状态 |
| `POST /api/event-center/government/tasks/:id` | state:accepted/completed、confirm:true |
| `POST /api/event-center/government/simulate` | 隔离运行四类事件，不写真实业务状态、不递送、不调用模型 |

政府端“运行隔离示例”展示先观察、再执行的4类事件、3条示例提醒和2项示例待办。自动化测试覆盖撤回授权、跨居民访问、字段更正、时间触发、版本过期、重启去重、失败重试和删除清理。尚未连接真实受理系统、短信和社区派单；没有预测模型、自动审批或自动提交。
